# RSA-2048 chat

New endpoint keys use a 2048-bit modulus and public exponent 65537. The chat
wraps a random 256-bit session master using RSA-OAEP with SHA-256 and MGF1-SHA256.
It derives separate AES-256-GCM keys for each direction with HKDF-SHA256.
Public session metadata is bound into the OAEP label and authenticated records.

## Run

After installing `requirements-network.txt`, create a new private key file:

```powershell
.\.venv\Scripts\python.exe chat.py setup --bits 2048 --key-file chat_keys_2048.json
```

Start Interceptor before the peers so it records the handshake:

```powershell
.\.venv\Scripts\python.exe capture.py --list-interfaces
.\.venv\Scripts\python.exe intercept.py --capture captures/rsa2048.jsonl --live --interface "<loopback interface>" --port 9001
```

Start Bob in another terminal, then Alice in a third:

```powershell
.\.venv\Scripts\python.exe chat.py listen --host 127.0.0.1 --port 9001 --name Bob --key-file chat_keys_2048.json
.\.venv\Scripts\python.exe chat.py connect --host 127.0.0.1 --port 9001 --name Alice
```

The two peers use the existing full-screen chat interface. Alice negotiates
RSA-2048 from Bob's public greeting. Private key files are never overwritten by
setup; existing RSA-33 and RSA-248 files keep their original profile. Use a new
filename when changing profiles. See [NETWORK_DEMO.md](NETWORK_DEMO.md) for
Npcap installation, interface selection, and Interceptor controls.

Version-3 captures contain a 256-byte OAEP ciphertext in `wrapped_key_hex`.
Versions 1 (RSA-33) and 2 (RSA-248) remain supported. The transport remains
custom framed TCP; it does not provide TLS or authenticated peer identities.

## Measured timings

Run the benchmark on the presentation machine:

```powershell
.\.venv\Scripts\python.exe benchmark_rsa.py --bits 2048 --trials 20
```

The checked-in `rsa2048_benchmark_report.json` records these medians on
4 November 2026, with Python 3.12.14 on Windows 11:

| Operation | Median | Trials |
| --- | ---: | ---: |
| Key generation | 494.35 ms | 20 |
| Private key load and validation | 39.17 ms | 20 |
| Session wrap | 0.63 ms | 20 |
| Session unwrap | 2.54 ms | 20 |
| Encrypt a 4096-byte message | 0.19 ms | 500 |
| Decrypt a 4096-byte message | 0.24 ms | 500 |

Each generated key, session secret, and encrypted message was round-trip
verified. Private-key construction and validation happen before the timed
unwrap, matching the endpoint's startup flow. These are local cryptographic
operation timings, excluding network transport and terminal rendering.

## Quantum recovery

Interceptor captures the public handshake and encrypted messages, but leaves
RSA-2048 messages queued when recovery is requested. The current dense-matrix
statevector circuit would project to 6144 qubits at this size. Its resource guard
rejects the request before allocating matrices or starting a simulator worker.
This projection describes this implementation, not every possible Shor circuit.

The report records `not_run_resource_limit` and a null quantum execution time.
There is no measured RSA-2048 quantum speedup or successful key recovery here.
Use the RSA-33 profile to demonstrate actual circuit execution and decryption.

## Tests

```powershell
$env:ACG_LIVE_CAPTURE_INTERFACE = "<loopback interface>"
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Without the environment variable, the two live-capture tests skip. RSA-2048
tests cover exact modulus size, default setup and key reload, bidirectional
handshakes, Unicode and 4096-byte records, OAEP and record tampering, simulator
preflight, and retained ciphertext. The opt-in live test starts actual endpoint
subprocesses and Npcap capture, verifies both message directions, confirms
Interceptor cannot decrypt, then stops capture and checks that chat continues.
